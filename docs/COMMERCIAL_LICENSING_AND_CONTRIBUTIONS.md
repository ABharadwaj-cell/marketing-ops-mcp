# Commercial licensing and contribution governance

## Who may do what?
Under the new [PolyForm Noncommercial public licence](../LICENSE), personal learning, experimentation, forking, modification and noncommercial sharing are welcome, subject to the licence's stated scope and exemptions. Use in a commercial product, paid skill package, reseller offering, monetized SaaS, commercial service or for-profit organization generally needs the copyright holder's separate written licence, unless permitted by the actual licence or an existing historical grant.

The project owner, `@ABharadwaj-cell`, makes decisions about the **official project**: its commercial licenses, official releases, feature direction, acceptance of pull requests and community invitations. These rights depend on ownership and contributor agreements; they do not prohibit independent clean-room development or override older MIT/Perimeter permissions.

## Contributing workflow
1. Fork the public repository and create a branch for a focused improvement; noncommercial testing is permitted.
2. Open an issue or pull request with rationale, synthetic tests, source provenance, security notes and expected behavior.
3. Maintainer reviews quality and compatibility. No automatic merge or community membership.
4. Before merging substantive original third-party code, agree on a **separately executed** CLA granting the project sufficient commercialization/sublicensing rights; an explicit assignment/exclusive licence is required if ownership of that contribution itself must be exclusive.
5. Only the maintainer or authorized merger accepts the PR once tests, rights checks and any needed agreements pass. Community access/invitation is a separate voluntary step.

**Do not represent a GitHub PR checkbox or DCO sign-off as a signed copyright assignment.** Contributors retain their own IP unless a separate effective agreement provides otherwise. Owners of third-party dependencies retain their licence terms. Forks that use earlier MIT copies may legally commercialize those earlier versions.

## GitHub protections (configure separately)
Protect `main` with pull request review and required checks; code-owner approval where available, with admin bypass disallowed if supported. On GitHub Free personal **private** repositories, branch protection enforcement may require a paid plan. To minimize risk, do not invite untrusted users as collaborators on the proprietary private repo; collect community PRs against the **public** repository.

## Commercial rights process
Obtain written authorization from the relevant rights holder(s) before paid distribution of code released only under Noncommercial. Record authorized company, version/commit, rights and usage scope, territory, term, fees, security and termination. Keep commercial agreements off public GitHub.

*Governance/policy record only; not a signed commercial agreement or legal advice.*
